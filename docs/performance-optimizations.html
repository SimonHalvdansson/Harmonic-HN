How each change reaches the user

The benchmark is only useful if it maps back to something a person actually does.

01

Deferred story preview capture

While browsing

Scrolling no longer records six off-screen transition layers.

The list used to continuously prepare title, image, metadata, index, summary, and comment-count graphics for a preview that most stories never open. Those layers are now attached only after a long press and remain active while the preview is visible.

The list does less GPU and CPU bookkeeping on every ordinary scroll frame; long-press previews keep their shared transition.

Measurement · simpleperf story scroll

StoryItem inclusive CPU
7.60% → 5.41%
Profile window
15 seconds

ImplementationCapture on intent, preserve the shared transition.See source

02

Deferred comment action capture

While reading comments

Ordinary comment scrolling stops recording action-dialog snapshots.

Every visible comment row previously maintained a recorded graphics layer in case the user long-pressed it. Capture is now attached only to the gesture that will open the action overlay—or to the source row while that overlay remains visible.

Large discussions spend less per-frame work on interactions the user has not requested; tap/long-press swapping still behaves correctly.

Measurement · simpleperf comment scroll

CommentItem inclusive CPU
2.61% → 1.23%
Interaction check
overlay rendered on emulator

ImplementationRecord only the activating row, then retain it for the overlay lifecycle.See source

03

Static story-row visibility

While browsing

Stable list rows no longer carry transition state that can never animate.

Story-list presentation is immutable while scrolling, yet summary, favicon, image, and comment-count visibility used animated layout wrappers. The list path now uses a static layout; animated visibility remains available where the non-list presentation actually changes.

This removes layout and transition bookkeeping from the hottest feed path without making the UI feel faster by shortening or disabling an animation.

Measurement · staged story trace

ImplementationUse static visibility for list rows; keep animations for mutable presentation.See source

04

On-demand WebView startup

When comments open

Reading comments no longer wakes Chromium in the background.

The integrated website renderer previously started after a delay even when the user stayed in the discussion. It now starts only when the website is initially visible or the sheet genuinely begins moving toward it.

The comments entrance and first scroll avoid competing with Chromium process startup. Users who reveal the website still get preloading after the first 2% of real sheet travel.

Measurement · CPU trace and thread inspection

Idle app threads
57 → 50
Workers started on real reveal
7 Chromium threads

ImplementationMove renderer cost from “comments opened” to “website requested.”See source

05

One-pass metadata indexing

When link context loads

A page's metadata is walked once instead of queried field by field.

OpenGraph, Twitter, author, publication, language, and image extraction each used a CSS selector that walked the document. A compact index now records the first metadata value for every key in one traversal while preserving the existing priority order.

Link previews can settle sooner, especially on pages with a large head or substantial document chrome, with no change to which title, author, image, or description wins.

06

Cached DOM ancestry scoring

When a page lacks a clean summary

Description fallback stops re-walking the same ancestor chain for every paragraph.

Finding useful article prose requires excluding navigation and boilerplate, recognizing article containers, normalizing text, and counting words. Ancestor decisions are now cached, while several per-candidate regular expressions became allocation-light character scans.

Pages without good description metadata produce useful link context much faster, with less garbage-collection pressure during preview generation.

Measurement · warmed microbenchmark

Median time
87.8% faster
Allocations per operation
61,153 → 17,368 (−71.6%)

ImplementationMemoize ancestry facts and scan characters without hot regex allocation.See source

07

Callback-cached connectivity

Whenever network policy is checked

A status read becomes a volatile field access, not a system-service query.

The production application graph now registers one default-network callback, seeds it from the active network, and keeps online/unmetered flags current. Calls fall back to the previous query only if callback registration fails.

This is intentionally a small-flow optimization: individual checks were already sub-millisecond, but repeated fetch, cache, and model-download decisions no longer cross into ConnectivityManager each time.

≈79,980× faster

ImplementationPay once for observation; make consumers read cached truth.See source

08

Batched tint persistence

When preview colors resolve

Five related preference mutations commit through one editor.

Persisting a favicon or image tint wrote its source, base color, palette key, result, and index through separate SharedPreferences edits. The portable key-value contract now supports a transactional update, with Android mapping it to one editor and one asynchronous apply.

Visual enrichment creates less main-thread allocation and preference bookkeeping as stories load their icons and preview imagery.

Measurement · warmed microbenchmark

Median time
58.7% faster
Allocations per operation
187 → 93 (−50.3%)

ImplementationAdd a portable batch contract and use one Android preferences editor.See source

09

Immutable state reuse

Whenever story state publishes

Publishing an already-immutable snapshot stops copying its collections.

The story store held immutable map and list values but called toMap() and toList() every time it assembled public state. The snapshot now shares those safe immutable values directly.

Feed refreshes, resource updates, and settings-driven publications create less short-lived garbage, reducing the chance that collection copying contributes to a future scroll-time collection pause.

Measurement · exact old/new collection operation

Median time
99.86% faster
Allocations per operation
105 → effectively zero

ImplementationReuse values whose immutable ownership is already established.See source

10

Allocation-light saved-item decoding

When returning to saved state

Restoring hundreds of saved entries no longer creates a substring and sequence pipeline per item.

The codec now scans the persisted value by index and parses integers and timestamps directly with overflow checks. It preserves sorting, malformed-entry skipping, numeric limits, and the original on-disk format.

Large bookmark, read-state, and history collections restore with less CPU time and about two-thirds fewer allocations, while existing user data remains compatible.

Measurement · 500 saved items

Median time
60.9% faster

6,867 → 2,388 (−65.2%)

ImplementationParse in place, reject overflow, preserve the storage contract.See source

Read the numbers honestly

Absolute microbenchmark times are emulator-specific. The relative comparisons are controlled. CPU-sample percentages come from staged traces; they should not be added together as if they were wall-clock savings. “Absent” means the optimized helper received no samples in the matching trace—not that the entire user flow became free.
